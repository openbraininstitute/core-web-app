PUBLIC WEBSITE PERFORMANCE CHANGES

Automatic home tour: 8 three-second previews, 1,057,162 bytes in total.
Previously their full sources totaled 55,615,812 bytes. Clicking a model
plays its complete movie. The white tiles retain movement, flips and hover;
only the selected model plays video. Other model tiles use still frames.
The previous decoder/download is released when selection changes.

Seven chapter movies: 67,657,276 -> 10,244,562 bytes (85% smaller).
Original duration and aspect ratio are preserved; audio is omitted because
these muted presentation films do not use it. Posters: 2,320,364 ->
1,429,550 bytes (38% smaller). Original source media is unchanged.

Rebuild optimized variants from the source masters:
  python3 scripts/website/optimize-media.py
  node scripts/website/optimize-posters.mjs
Requires ffmpeg/ffprobe and the project's sharp package. Review image quality
before replacing deployed variants. Change the encoding recipe version if
changing settings; variant URLs include a hash of the source and recipe.
Generated variants in public/static/website-optimized MUST ship with the app;
optimized-media.json records their names and sizes. They are not ignored by Git.

Other changes:
- Only start model video after browser idle, or an 800ms fallback.
- Stop video downloads and canvas rendering offscreen or with the tab hidden.
- Cap the landing canvas at 30fps and pixel ratio 1.5.
- Initialize the shared chapter WebGL field only after entering chapters.
- Replace the chapter wrapper's permanent animation-frame polling with events.
- Calculate desktop landing geometry in CSS before the first paint.
- Public homepage has no server session or feature-cookie lookup, and no full
  platform provider initialization. Real sign-in happens after the platform CTA.
- Defer original in-app home and floating 3D components; separate recorded
  chapter components from the live 3D viewer module.
- Stripe uses its pure entry point; the external billing script starts when
  getStripe is actually called, rather than when a module is imported.
- Homepage retains request-time rendering: the root layout injects deployment
  configuration at runtime. Static pre-rendering would serialize the build-time
  empty configuration placeholder and prevent client startup. Session lookup
  remains removed from the public homepage. Protected /app routes are unaffected.
- Preload the public information font and logo face; other platform fonts load
  on use, instead of competing for initial bandwidth.
- Versioned optimized media has one-year immutable cache headers.
