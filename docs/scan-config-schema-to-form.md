# Schema to Form Generation in Scan Config

## Overview

The scan-config feature dynamically generates forms from JSON schemas fetched from the OBI-ONE API. The system uses a three-column layout:
- **Left Panel**: Navigation menu showing root elements grouped by category
- **Middle Panel**: Form fields for the selected element
- **Right Panel**: Model preview

## How Schema-to-Form Generation Works

### 1. Schema Fetching (`useObioneJsonSchema`)

The schema is fetched from `${OBI_ONE_URL}/openapi.json` and dereferenced using `@apidevtools/json-schema-ref-parser`. The specific schema (e.g., `CircuitExtractionScanConfig`) is extracted from `components.schemas`.

### 2. UI Element Types

The system recognizes specific `ui_element` values to determine how to render each schema property:

| `ui_element` | Description | Rendered Component |
|--------------|-------------|-------------------|
| `root_block` | Top-level form section with direct fields | `BlockUI` component |
| `block_dictionary` | Collection of typed blocks (expandable menu) | Selection buttons + `BlockUI` |
| `string_input` | Text input field | Ant Design `Input` |
| `boolean_input` | Toggle switch for boolean values | `BooleanInput` component |
| `model_identifier` | Read-only model details | `ModelDetails` component |
| `float_parameter_sweep` | Numeric input with sweep support | `ParameterSweep` component |
| `int_parameter_sweep` | Integer input with sweep support | `ParameterSweep` component |
| `reference` | Reference to another block | `Reference` dropdown |
| `neuron_ids` | List of neuron IDs | `NeuronIds` component |
| `entity_property_dropdown` | Dropdown from entity properties | `EntityPropertyDropdown` |

### 3. Left Menu Generation

The left menu is generated by iterating over `schema.group_order` and rendering `RootElement` components for each property that matches the current group:

```tsx
{schema.group_order.map((group) => (
  <>
    <div>{group}</div>
    {Object.entries(schema.properties)
      .filter(([_, rootElementSchema]) => rootElementSchema.group === group)
      .sort((a, b) => a.group_order - b.group_order)
      .map(([k, rootElementSchema]) => (
        <RootElement key={k} ... />
      ))}
  </>
))}
```

### 4. Middle Form Generation

The middle panel renders forms based on the selected root element:

1. **For `root_block`**: Directly renders `BlockUI` with the block's properties
2. **For `block_dictionary`**: 
   - Shows block type selection buttons when no block is selected
   - Renders `BlockUI` for the selected block type

The `BlockUI` component iterates over `blockSchema.properties` and calls `renderInput()` for each field based on its `ui_element`.

## Why Your Schema Generates the Left Menu But Not the Middle Form

### The Problem

Looking at your `CircuitExtractionScanConfig` schema:

```json
{
  "properties": {
    "info": {
      "group": "Setup",
      "group_order": 0,
      "properties": {
        "campaign_name": { "ui_element": "string_input", ... },
        "campaign_description": { "ui_element": "string_input", ... }
      }
      // ❌ MISSING: "ui_element": "root_block"
    },
    "initialize": {
      "group": "Setup",
      "group_order": 1,
      "properties": {
        "circuit": { ... },  // ❌ No ui_element
        "do_virtual": { ... },  // ❌ No ui_element
        "create_external": { ... }  // ❌ No ui_element
      }
      // ❌ MISSING: "ui_element": "root_block"
    },
    "neuron_set": {
      "group": "Extraction Target",
      "group_order": 0,
      "oneOf": [ ... ]
      // ❌ This is a discriminated union, not a block_dictionary or root_block
    }
  }
}
```

### Root Causes

#### 1. Missing `ui_element` on Root Properties

The `info` and `initialize` properties are missing the `ui_element: "root_block"` attribute. The code explicitly checks for this:

```tsx
// In middle.tsx
{isRootBlock(schema, configTab) || selectedBlockSchema) && (
  <BlockUI ... />
)}

// In schema.ts
export function isRootBlock(schema: ConfigSchema, key: string) {
  return schema.properties?.[key]?.ui_element === 'root_block';
}
```

Without `ui_element: "root_block"`, the condition `isRootBlock(schema, configTab)` returns `false`, and no form is rendered.

#### 2. Missing `ui_element` on Nested Properties

The nested properties inside `initialize` (like `circuit`, `do_virtual`, `create_external`) don't have `ui_element` attributes. The `renderInput()` function in `components.tsx` only handles specific `ui_element` values:

```tsx
function renderInput(k: string, paramSchema: ParamSchema) {
  if (paramSchema.ui_element === 'string_input') { ... }
  if (paramSchema.ui_element === 'model_identifier') { ... }
  if (paramSchema.ui_element === 'float_parameter_sweep') { ... }
  // etc.
  return null; // Returns null for unrecognized ui_element
}
```

#### 3. `neuron_set` Uses `oneOf` Instead of `block_dictionary`

The `neuron_set` property uses a discriminated union (`oneOf` with `discriminator`) but doesn't have `ui_element: "block_dictionary"`. The system expects:

```json
{
  "ui_element": "block_dictionary",
  "reference_type": "...",
  "singular_name": "...",
  "additionalProperties": {
    "oneOf": [...]
  }
}
```

But your schema has:
```json
{
  "oneOf": [...],
  "discriminator": {...}
}
```

## How to Fix the Schema

### Option 1: Add `ui_element` Attributes

```json
{
  "properties": {
    "info": {
      "ui_element": "root_block",  // ✅ Add this
      "group": "Setup",
      "group_order": 0,
      "properties": {
        "campaign_name": { "ui_element": "string_input", ... },
        "campaign_description": { "ui_element": "string_input", ... }
      }
    },
    "initialize": {
      "ui_element": "root_block",  // ✅ Add this
      "group": "Setup",
      "group_order": 1,
      "properties": {
        "circuit": { 
          "ui_element": "reference",  // ✅ Or appropriate type
          "reference_type": "Circuit",
          ...
        },
        "do_virtual": { 
          "ui_element": "boolean_input",  // ✅ Now supported
          ...
        }
      }
    },
    "neuron_set": {
      "ui_element": "block_dictionary",  // ✅ Change structure
      "reference_type": "NeuronSet",
      "singular_name": "Neuron Set",
      "group": "Extraction Target",
      "group_order": 0,
      "additionalProperties": {
        "oneOf": [...]  // ✅ Move oneOf here
      }
    }
  }
}
```

### Option 2: Extend the Code to Handle Missing `ui_element`

Add fallback handling in the codebase for schemas without explicit `ui_element` values.

## Summary Table

| Schema Property | Has `ui_element`? | Left Menu Shows? | Form Renders? | Why? |
|-----------------|-------------------|------------------|---------------|------|
| `info` | ❌ No | ✅ Yes (has `group`) | ❌ No | Missing `ui_element: "root_block"` |
| `initialize` | ❌ No | ✅ Yes (has `group`) | ❌ No | Missing `ui_element: "root_block"` |
| `neuron_set` | ❌ No | ✅ Yes (has `group`) | ❌ No | Uses `oneOf` directly, not `block_dictionary` structure |

The left menu renders because it only checks for `group` and `group_order` properties. The middle form doesn't render because it requires specific `ui_element` values to determine which component to use.
