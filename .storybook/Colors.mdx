# Colors

Every color in the design system is a CSS variable defined in
[`src/styles/globals.css`](../src/styles/globals.css) inside the `@theme` block. Tailwind
turns them into utility classes automatically: `--color-primary-9` becomes
`bg-primary-9`, `text-primary-9`, `border-primary-9`.

**Rule:** primitives never use hex literals. If a color isn't in `@theme`, add it
there first.

## Drift to fix

While documenting the palette I noticed these usages that don't go through tokens:

- **`src/ui/molecules/badge/index.tsx`** uses `bg-red-500` for the `destructive`
  variant instead of `bg-destructive` (defined in `@theme`).
- **`src/ui/molecules/button/index.tsx`** uses `bg-destructive` ✅ — Badge should
  match.
- A handful of segments use `dark:` Tailwind classes without a corresponding dark
  theme being defined. Either define dark tokens or remove the classes.

Track these as a token-audit task before adding new primitives.
