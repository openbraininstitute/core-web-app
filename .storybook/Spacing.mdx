# Spacing & Layout

Tailwind v4's default spacing scale is in play (`p-1` … `p-96`), plus a handful of
project-specific tokens defined in
[`globals.css`](../src/styles/globals.css).

> Remember the 14px root font size — `p-4` resolves to `0.875rem` × 4 = 14px × 1 = **14px**
> (vs 16px in a default Tailwind project).

---

## Layout tokens

### Shadows

Defined as `--shadow-*` and exposed as `shadow-strong-image`, `shadow-super-shadow`,
`shadow-bnb`, `shadow-lift`, `shadow-lift-hover`, `shadow-lift-active`, `shadow-skmp-s`.

`shadow-lift` is the convention for elevated cards in this design system. Prefer it
over reaching for `shadow-md` or `shadow-lg`.

### Easings

`--ease-in-expo`, `--ease-out-expo`, `--ease-out-back`, `--ease-smooth` are available as
`ease-in-expo` etc. for `transition-timing-function`. Use these on hover/expand
animations to keep motion consistent across primitives.

### Animations

Reusable keyframes registered as `--animate-*`: `slide-out`, `slide-up`, `scale-down`,
`scale-up`, `fade-in`, `fade-out`, `rotate`, `shimmer`. Apply with `animate-fade-in`,
`animate-rotate` etc.

---

## Conventions

1. **Component padding is symmetric and rem-based.** Use Tailwind's `p-*` /
   `px-*` / `py-*`, not custom pixel values.
2. **Gaps over margins.** Use `gap-*` on flex/grid parents instead of margins
   between children.
3. **`vw`/`vh` tokens are for layout primitives**, not for individual components.
   A button shouldn't depend on viewport size.
4. **Avoid arbitrary spacing values** (`p-[13px]`). If you need a value not in the
   scale, add it as a token to `globals.css`.
